# Statistical Analysis Specification

Status: authoritative planning and interpretation specification

Dataset: completed Phase 5B Orders-recovery campaign, 100 valid runs

Cost boundary: credit-free; no model calls are required by this specification

## Purpose

This project studies variation across repeated agent executions. Statistical analysis means describing that variation, comparing deliberately recorded conditions, quantifying uncertainty, and making limited associational explanations.

The primary experimental unit is one fresh agent run. Tool calls and actions are nested observations inside a run; they are not independent experimental replicates.

## Statistical objects

For run $r=1,\ldots,R$, define:

$$
Z_r=\text{controlled experimental condition},
$$

$$
\mathbf X_r=(X_{r1},\ldots,X_{rN_r})=\text{ordered observable execution path},
$$

$$
N_r=\text{MCP call count},\quad
L_r=\text{total latency},\quad
T_r=\text{token count},\quad
C_r=\text{estimated cost},
$$

$$
Y_r=\begin{cases}1,&\text{success},\\0,&\text{failure},\end{cases}
$$

and $H_r$ for derived observable histories such as the action immediately following a rejected escalation.

The realized run is a possible outcome $\omega_r$. The study observes repeated realizations

$$
\omega_1,\ldots,\omega_R,
$$

without needing to know the agent's internal probability distribution.

## Claim levels

### Descriptive

What happened in the collected runs? Examples include empirical means, medians, proportions, path frequencies, and entropy.

### Inferential

What may be expected of another fresh run under essentially the same task, model, prompt, tools, environment, and acquisition setup? Confidence and bootstrap intervals quantify sampling uncertainty; they do not generalize to agents in general.

### Associational

Which observed quantities occur together? For example,

$$
P(Y=1\mid H),
\qquad
E[L\mid N=n],
\qquad
\operatorname{Corr}(T,C).
$$

These are not automatically causal effects.

### Causal

A causal claim requires deliberate assignment of an intervention. The existing Phase 5 runbook behaviour was generated by the agent, not assigned by the experiment, so the present result is observational.

## Question protocol

Every question in `analysis_questions.yaml` must specify a practical question, unit, variables, estimand, inclusion rule, method, uncertainty method, output, acceptance criteria, interpretation, and limitation.

The implementation must follow this order:

1. Define the question and estimand.
2. Identify the run-level variables.
3. Check data completeness and measurement reconciliation.
4. Describe the relevant distributions.
5. Calculate the estimate and uncertainty.
6. Produce the required table or plot.
7. Write the practical interpretation and limitation.
8. Verify the result against the acceptance criteria.

## Analysis questions

### Q01 — What is one observation?

Document the run as the experimental unit, classify every variable, and distinguish measured, derived, and unavailable quantities.

### Q02 — What distribution does each run-level outcome have?

For counts and continuous outcomes, report mean, median, quartiles, standard deviation, range, empirical CDF, histogram, and extreme values. The distribution is the scientific object; a single mean is insufficient.

### Q03 — Are repeated runs stable?

Compare success, calls, latency, tokens, cost, path entropy, and runbook-first behaviour across acquisition batches. Treat this as a stability diagnostic, not a confirmatory time-series test.

### Q04 — Does workload vary with experimental condition?

For $N_r$, compare $E[N\mid Z=z]$ and relevant call-count ratios. Use Poisson or negative-binomial regression only after inspecting count dispersion and preserving the run-level unit.

### Q05 — Do more MCP calls associate with longer runtime?

Inspect $(N_r,L_r)$ and use the descriptive model

$$
L_r=\beta_0+\beta_1N_r+\varepsilon_r.
$$

Interpret $\beta_1$ as an association, not automatically the causal time of one extra call.

### Q06 — Where does runtime go?

Use

$$
L_{\mathrm{total},r}=L_{\mathrm{model},r}+L_{\mathrm{MCP},r}+L_{\mathrm{orchestration},r}.
$$

Show component distributions, shares, ranges, and correlations. Handler time remains nested inside MCP time.

### Q07 — What explains tokens and cost?

Compare $C_r$ and $T_r$ with MCP calls, runtime, and path length using plots and rank correlations before fitting any regression.

### Q08 — Which observable histories associate with failure?

For each predeclared history $H$, estimate

$$
\widehat P(Y=0\mid H).
$$

Report counts, percentages, Wilson intervals, risk differences, and exact tests where appropriate. Perfect separation is reported directly rather than hidden behind an unstable logistic coefficient.

### Q09 — What is the distribution of complete paths?

Estimate

$$
\widehat P(\mathbf X=x)=\frac{\#\{r:\mathbf X_r=x\}}{R}
$$

and report unique paths, singleton paths, modal coverage, cumulative top-$k$ coverage, path length, outcome by path, and

$$
H(\mathbf X)=-\sum_xP(\mathbf X=x)\log_2P(\mathbf X=x).
$$

Entropy summarizes the distribution; it does not replace it.

### Q10 — What events follow other events?

For adjacent states, report

$$
n_{ij}=\#\{X_t=i,X_{t+1}=j\},
\qquad
\widehat p_{ij}=\frac{n_{ij}}{\sum_jn_{ij}}.
$$

These are empirical transition summaries. No Markov assumption is made.

### Q11 — How much extra work occurs?

For successful runs, define

$$
E_r=N_r-N_r^*,
$$

where $N_r^*$ is the shortest valid oracle length. Report exact-oracle success, excess calls, repeated tools, unexpected actions, and oracle distance. Do not invent successful-path excess for failed runs.

### Q12 — When does a trace first diverge?

Define the first observable oracle divergence position $D_r$. Compare its distribution across success, failure, and path families. This is a tool-sequence position, not a private reasoning step.

### Q13 — Which tools dominate work?

Report tool invocation count, invocation proportion, run coverage, and successful-run coverage. Per-tool bytes and latency are unavailable unless instrumentation changes; current frame bytes and latency are run-level quantities.

### Q14 — Are path, workload, and failure related?

Compare path families on success, calls, runtime, tokens, cost, and excess actions. Treat path family as an observed feature, not a randomized treatment.

### Q15 — What would a causal experiment require?

Keep intervention design separate from current results. A future assigned action $A_r$ could compare

$$
P(Y=1\mid A=1)-P(Y=1\mid A=0),
$$

but no such intervention occurred in Phase 5 and none is required for this credit-free program.

## Interpretation limits

- Fresh sessions support run-level experimental units but do not prove identical distributions over time.
- Actions within a run are nested and should not inflate the sample size.
- Observed branch choices are not interventions.
- Perfect separation in the synthetic world is not a universal agent-reliability law.
- Local stdio MCP/JSON-RPC frame bytes are not HTTP, TLS, TCP, or IP packet measurements.
- Current instrumentation does not measure queue waiting, utilization, arrival processes, or network RTT.
- Exploratory questions must not be presented as independent confirmatory discoveries merely because many $p$-values were calculated.

## Definition of done

Every question must have a reproducible artifact, a plain-language result, uncertainty where appropriate, an explicit limitation, a linked acceptance test, and a traceable entry in the question registry.
